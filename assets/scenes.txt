# The scenes the game can load, and what each one is made of.
#
# Five fields, all required. `-` means none. Blank lines and `#` comments are
# fine. A malformed row costs the whole file, not just itself - see
# src/scene/scene_list.h for why, and for what each field means.
#
# spawn is `terrain` (stand on the ground under the spawn column) or `floor`
# (stand on the world border). A scene naming no material map must use `floor`,
# because it has no terrain to scan.
#
# Three optional fields follow (V26, 2026-08-24): `mode`, then `width height` as
# a pair. mode is `fixed` (solid world borders, camera clamped, each backdrop
# layer panned across its own width exactly once so nothing repeats) or
# `infinite` (unbounded horizontal travel, backdrop layers tiled). Omitted, a
# row means `fixed`, which is what every row written before the column existed
# meant. Omitted, the size is the material BMP's own, or the engine default for
# a scene that names no BMP.

# name     material           albedo           props           spawn    mode      width  height
empty      -                  -                -               floor    infinite  1920   1080

# **V28's authored nine-layer backdrop set (art_src/Background_1).**
#
# The world is 344x144 *cells* and the art is 344x144 *pixels*, and those are the
# same 344x144: one art pixel is one world cell. That mapping is what sets how
# big the player looks against the scene, and it was measured off the tester's
# reference (IMG_0195.PNG) rather than chosen - the player's 12 opaque columns
# against the scene's 344. At two cells per art pixel the player is half the
# size the reference shows.
#
# The scale column is therefore 10 and not the engine's 4: at 4 px/cell this
# world would be 1376x576 screen pixels, smaller than the window, so the window
# could not be a view *into* it. At 10 a 1920x1080 window shows 192x108 cells of
# the scene and a 3440x1440 one shows all 344x144 - which is exactly the
# reference frame.
#
# **`fixed`, and the V27 comment that used to sit here argued the opposite.**
# That comment said `infinite` was load-bearing because the fixed branch ignores
# the parallax factors. It was right about the code and wrong about the geometry:
# it was written when the art was stretched to the window, so only tiling could
# fill the travel. Now the art is exactly world-sized, and a world-sized layer at
# any factor <= 1 covers the viewport at every camera position with no tiling and
# no gap (the arithmetic is at `draw_backdrop_layer`, pinned by `camera_test`).
# What V28 changed is that reading the factors and tiling are now two questions
# instead of one flag - `infinite` here would repeat nine images that do not
# tile, which is nine seams sliding at nine speeds.
#
# **It names a material and albedo map, so it is not an empty scene any more.**
# The maps are generated by tools/convert_background_layers.py: rows 132..143 are
# Wall, everything above is Empty. That gives the body something to stand on at
# the height the reference shows, found by `spawn terrain`'s own scan rather than
# by a constant - and it makes the bottom band real, diggable matter.

# name     material          albedo          props  spawn    mode   width height scale
bg1        bg1_material.bmp  bg1_albedo.bmp  -      terrain  fixed  344   144    10
